How to use this page

  1. Paste JSON, a log line, or any text that contains JSON into Input. The output updates as you type. Sample loads an example.
  2. JSON stored inside a string is formatted too. It is tagged JSON string when the whole string is JSON, and contains JSON when there is text around it.
  3. When the JSON is a log entry, the blue strip above the output shows its application, module, transaction ID and merchant ID.
  4. Click any { or [ to fold it. Collapse folds everything below the top level and Expand opens it again.
  5. Copy copies the output with the indent you picked.

You can also drop a .json file anywhere on the page. A− and A+ change the text size.

  1. In Grafana, open the logs panel menu and choose Inspect, then Data, then Download CSV.
  2. Open the Log viewer tab and choose that file, or drop it anywhere on the page. JSON arrays and newline-delimited JSON work too.
  3. The summary shows where the logs came from and lists every module, trace, ID and log type. Click one to filter the list, and click it again to remove the filter.
  4. Rows are in time order. The +664 ms next to each time is the gap since the previous row. Orange means 250 ms or more and red means 1 s or more.
  5. Click a row to see its message and fields. Press j and k, or use Next and Prev, to read the entries one at a time.
  6. Exceptions and errors get a red or amber badge, even when they were logged at Information level. Click Exceptions or Errors under Problems in the summary to list only those.
  7. Share sends this exact view, list or flow with its filters and open entries, as a link or as an HTML file. The link suits a few hundred entries. For bigger files, send the HTML file, because chat apps cut off long links.
  8. Fields that are the same in every entry are hidden from each row and listed once in the summary. Untick Hide common fields to see them in every row.
  1. In the log viewer, switch the toolbar from List to Flow to see the calls between Merchant, PayFuture and Provider.
  2. Solid blue arrows are requests. Dashed green arrows are responses, labelled with the time since their request and the status code. Orange arrows are provider webhooks and merchant callbacks.
  3. Log lines between calls collapse into internal steps. A pause of 2 seconds or more shows as a red divider, which is usually a wait for a webhook.
  4. A red ⚠ Exception box marks an exception and an amber ⚠ Error box marks a logged error. A red arrow is a failed response, such as Unauthorized or a 4xx or 5xx status. Hover over a box to see the stack trace.
  5. Some integrations log their provider calls without a LogType. For those, arrows come from messages like "SubmitPayout request: {...}" and are marked inferred.
  6. Hover over an arrow to see its payload, formatted. Click the arrow to open the entry in the list, and use ← Back to flow to return to the same spot.
  7. Click a trace in the summary to see one request's flow on its own.

Arrows come from each entry's LogType. Other entries count as internal steps unless they are exceptions or errors.

  • Everything runs in your browser and the page loads no outside scripts. Nothing you paste or open is uploaded, unless you make a short link.
  • Theme, text size, indent and the other options are saved in this browser and come back on your next visit.
  • Pasted text and the open log file survive a refresh. The browser deletes them when you close the tab, and Clear deletes them straight away.
  • A short link stores an encrypted copy on jsonblob.com, and the key to it is only in the link. A full link or file carries the data itself. Either way, anyone who has the link or file can read the data. Sensitive values are masked by default: passwords, tokens, secrets, account numbers, names, emails and phone numbers. Masking goes by field name, so check the shared view before sending it.
  • Log exports can contain account numbers, names and credentials. Share them with care.
